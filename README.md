# Nocturne Planet

のくぷら公式HPとDiscord認証付きの会員・スタッフ・運営ページ。Cloudflare Pages / Pages Functions / D1で動作し、画像をイベント用Google Driveへ非公開で保存します。

公開URL：<https://nocturne-planet.pages.dev/>。GitHubの `main` 更新後に検証・公開します。

公式YouTube：<https://www.youtube.com/@NocturnePlanet>。サイト設定から変更でき、埋め込み動画は個別に選択します。

| ページ | URL | 利用条件 |
| --- | --- | --- |
| 公式HP | `/` | 誰でも閲覧 |
| キャスト・スタッフ募集 | `/recruit` | 誰でも閲覧 |
| 会員 | `/member` | お客さん用Discordサーバーのメンバー |
| キャスト・スタッフ | `/staff` | 運営用Discordサーバーのメンバー |
| 運営 | `/manage` | 運営用サーバーの「運営」ロール |

`/staff` と `/manage` は公開ナビに載せず、すべての専用APIで現在のDiscord所属・ロールを確認します。

## 機能

- 運営：記事・固定ページ・マニュアルの下書き、プレビュー、公開、非公開。営業日時・回答締切・合言葉・キャスト紹介・公式リンクの編集。
- 全キャスト・スタッフ：出欠・参加可能時間・対応できる担当の回答、マニュアル閲覧、本人宛ての配置確認、チェキ送信と表示取り消し。
- 会員：合言葉によるチェックイン、来店記録、お気に入り登録、チェキ受信・保存。

配置は運営が決定して本人に案内します。会員はDiscordユーザーIDで識別し、表示名の変更で履歴を分けません。選択時のログイン保持は30日間です。

## 開発と確認

Node.js 24を使います。

```sh
npm ci
npm run db:local
npm run dev
```

開発URLは `http://localhost:8787`。必要な開発用秘密情報は `.dev.vars.example` を参考に `.dev.vars` へ置きます。秘密情報をGitに含めません。

```sh
npm run check
npm test
npm run build
```

公開物は `dist` のみです。ソース・テスト・秘密情報を公開フォルダにコピーしません。SQLiteとDiscord/Driveのテスト応答を使い、権限、CSRF、OAuth、他人の画像取得、二重チェックイン、出欠締切などを検証します。

`node tests/preview.mjs` はブラウザー確認専用です。127.0.0.1:8788だけで動作し、架空の検証データと認証を使います。本番の認証確認には使えず、公開物にも含めません。

## 初回の公開設定

1. PagesをGitHubへ接続します。ビルド：`npm run check && npm test && npm run build`、出力：`dist`、Node.js：24。
2. D1を作成して `wrangler.jsonc` のIDを合わせ、`npx wrangler d1 migrations apply DB --remote` を実行します。初回を管理画面で適用した場合は `d1_migrations` に適用済みファイル名も記録します。
3. 本番の変数・秘密情報を設定して再公開します。プレビューに本番秘密情報をコピーせず、自動プレビュー公開も無効にします。
4. Discordアプリの戻り先：`https://公開ホスト/auth/discord/callback`。スコープ：`identify guilds.members.read`。メール取得は不要です。
5. 運営ページの「スタッフ一覧」と出欠の締切通知を使う場合は、同じアプリのBotを運営用サーバーに追加します。Developer Portalの「Bot」で **Server Members Intent** を有効にし、権限なし（招待URLの `permissions=0`）で招待します。トークンを `DISCORD_BOT_TOKEN` に登録します。Botはメンバー一覧とロールを読み、出欠の締切前に未回答の人へDMを送ります。サーバーのチャンネルへの投稿やロールの変更はしません。
6. VRChat名をお客様用サーバーのニックネームにも反映する場合は、同じBotをお客様用サーバーにも追加し、**ニックネームの管理**（`permissions=134217728`）を許可します。Botのロールを、名前を更新するお客様のロールより上へ置いてください。管理者権限は不要です。サーバー所有者とBot以上のロールの人の名前は変更できません。
6. Google CloudでDrive APIとOAuthウェブクライアントを用意します。戻り先：`https://公開ホスト/auth/google/callback`。スコープ：`openid email https://www.googleapis.com/auth/drive.file`。
7. 運営ロールで `/manage` にログインし、「サイト設定」からイベント用Google Driveを連携します。初回に画像用フォルダを作ります。

Google OAuthをExternal / Testingのまま使うと、Driveの更新トークンが短期間で失効します。継続運用では公開ステータスと必要なブランド設定を確認してください。

| 設定名 | 内容 | 扱い |
| --- | --- | --- |
| `APP_ORIGIN` | 本番の `https://ホスト` | 公開設定 |
| `STAFF_GUILD_ID` | 運営用サーバーID | 公開設定 |
| `CUSTOMER_GUILD_ID` | お客さん用サーバーID | 公開設定 |

## 保存と運用

VRChat連携は会員ページとスタッフページから行います。プロフィールURLを登録し、発行したコードだけを自己紹介に1行で載せてから「確認する」を押すと、自動で本人確認します。確認後は自己紹介からコードを削除できます。本人確認にはイベント専用アカウントで公開プロフィールを読み取ります。利用者のVRChatパスワードや認証情報は預かりません。

コードは30分・10回まで有効で、確認は30秒に1回です。同じVRChatアカウントは複数のDiscordアカウントに連携できません。プロフィールは確認時だけ取得し、保存するのはユーザーID・表示名・確認日時です。連携を解除してもDiscordに紐付く来店記録やチェキは保持します。専用ページの所属・ロール判定は引き続きDiscordで行います。

連携した会員の表示名は、確認済みのVRChat名を優先します。会員ページの見出しとヘッダーは、連携・解除の直後から切り替わります。元のDiscord表示名は別に保持するため、再ログインしてもVRChat名は失われず、解除時はDiscord表示名に戻ります。スタッフ・運営ページの表示名とキャスト紹介名は変えません。

会員ページでの連携完了時と、連携済み会員がページを開いたとき、お客様用Discordサーバーのニックネームを自動で同期します。Discord側は空白を整え、先頭32文字に収めます。VRChatの名前を更新した場合は、もう一度本人確認すると新しい名前を取得します。ニックネームの更新結果を保存し、権限不足・接続失敗時も会員ページとVRChat連携は利用できます。同期ボタンは表示せず、失敗時は5分後以降に再試行します。ページを開いている間も自動で再試行し、別タブを見ている間は待機します。Discordの回数制限中は指定時間を待ちます。連携解除で同期記録を消しますが、Discordのニックネームは自動では元に戻しません。`0008_discord_nickname_sync.sql` が未適用の場合も、最初の利用時に同じテーブルを作成します。

接続が切れた場合はWindowsで `python -X utf8 scripts/connect-vrchat.py` を開き、イベント専用アカウントを再接続します。パスワードは保存しません。接続情報はGit対象外の `artifacts/vrchat-session.dpapi` に、このWindowsユーザーだけが復号できる形で保存します。本番では接続トークンをCloudflare PagesのProductionの秘密情報へ登録し、再公開します。取得を拒否された場合は接続経路を確認し、アクセス制限を回避する処理は行いません。

通常の営業曜日・時刻は、運営ページの「通常営業」で設定します。毎週／隔週、曜日、開始・終了時刻を保存すると、公開HPと未回答の出欠フォームに反映されます。未定の場合は「未設定」のままにできます。営業回ごとの日付・公開・回答期限は「営業情報」で登録してください。

「営業を追加」では、次に来る営業曜日の日付と通常の開始・終了時刻を初期表示します。深夜をまたぐ終了日は翌日になります。隔週の基準日は未設定のため、開催する週は日付欄で確認・変更してください。既存の営業情報の日時は変更しません。

営業情報の「営業ラベル」で通常営業・特別営業などを指定できます（任意の名前、24文字以内）。新規登録の初期値と既存データは「通常営業」です。ホームの営業情報右下から `/schedule` の「今後の営業予定」へ移動できます。公開済みで終了前の営業を日時順に掲載し、非公開・終了済みの営業と内部のチェックイン情報は一覧に出しません。

出欠の参加時刻は、未回答なら通常営業時間を初期表示します。通常営業が未設定なら、その営業回の開始・終了時刻を使います。回答済みの時刻や空欄は、通常営業を変更しても上書きしません。

出欠の担当は、運営用Discordで本人に付いている担当ロールの項目だけ選べます。運営ロールが付いている人は、担当ロールに関係なくすべての担当を選べます。担当ロールがなくても、担当を空欄にして出欠と連絡事項は回答できます。保存時にも現在のロールを確認し、権限のない担当を含む回答は保存しません。既存の回答は勝手に書き換えず、ロール変更後の画面で選べなくなった担当を案内します。ロールを作り直した場合は `src/duties.mjs` の対応IDも更新してください。

運営ページの「スタッフ一覧」は、`DISCORD_BOT_TOKEN` を設定すると運営用サーバーのメンバーと担当ロールをBotで読み込みます。運営ページを開いたとき、前回の取得から5分以上たっていれば自動で取り直し、「Discordから再取得」ですぐに更新できます。ロールを付けた人は、スタッフページへのログイン前から配置の案内とキャスト紹介の紐付けに選べます。サーバーを抜けた未ログインの人は次の取得で一覧から外れます。取得に失敗しても運営ページは開け、ログイン済みのスタッフは従来どおり選べます。トークンが未設定の間は、スタッフページにログインした人だけを表示します。

「スタッフ一覧」では営業回を選ぶと、担当ロールがある人の出欠の回答状況（参加・欠席・未定・未回答）と、締切通知の送信状況を確認できます。「未回答の人だけ表示」で絞り込めます。「出欠の一覧」でも、選んだ営業回の未回答者を回答の下に表示します。出欠の対象は、運営用サーバーで担当ロール（`src/duties.mjs`）が付いている人です。

営業情報に出欠の回答期限を設定すると、対象の未回答者へ期限の12時間前・1時間前・5分前にDiscordのDMを送ります。各段階は1人1回で、回答した人には送りません。初回の確認が遅れた場合は、その時点で一番近い段階だけを送ります。回答期限を変えると、新しい期限に合わせて送り直します。DMを受け取らない設定の人は「DMを受け取らない設定」と表示します。

Cloudflare Pagesは定期実行ができないため、`cron-worker` の小さなWorkerが1分ごとに `/api/cron/reminders` を呼びます。PagesとWorkerの両方に同じ `CRON_SECRET` を秘密情報として登録し、`cd cron-worker` → `npx wrangler deploy` で公開します。`CRON_SECRET` が未設定の間は通知は動きません。

チェキはDriveで非公開のまま保存します。サイトが受取人・送信者の現在の所属を検証してから中継し、DriveのファイルIDや共有URLを返しません。運営ロールだけでは他人宛てのチェキを閲覧できません。Driveアカウントの管理者は保存先そのものを管理できます。

画像はJPEG・PNG・WebP、保存時4MBまで。画面側で長辺2400px以下のWebPに整え、位置情報等の付加データを除きます。公開記事・キャスト紹介の写真は、公開中の項目で使われている場合だけ認証なしで表示します。

運営ページの「サイト設定」では、開催場所・会場URL、本編／アフターの所要時間、3つのプログラムの見出し・時間・補足・紹介文・吹き出し・写真、施設紹介の案内文と3枚の写真・見出し・説明を変更できます。設定がない項目は現在のホームと同じ初期値を使います。プログラムの合計時間が本編を超える設定は保存できません。開催ペースの補足は、通常営業の曜日・時刻を設定している場合もその下に表示します。入場方法・開催場所は、次回の日程が未定のときも反映します。

トップ写真は12枚まで登録でき、ホームの背景で6秒ごとに切り替わります。並び順の変更と取り外しもできます。写真がない間は同梱の施設写真3枚を使います。プログラムと施設紹介の写真も同梱写真から選べ、新しい写真のアップロードにはGoogle Drive連携が必要です。選ばれている公開用の画像だけを認証なしで表示し、使用をやめた画像は他の公開記事やキャスト紹介でも使われていなければ公開されません。

公式X・YouTubeのURLを変更すると、ホームのヘッダーとSNS欄の両方へ反映します。URLが空欄なら該当リンクを隠します。Discordの招待URLが空欄ならホームとログイン画面の招待リンクを隠します。埋め込み動画のIDが空欄の場合は準備中と表示します。以前の管理画面や一部項目だけの設定保存でも、送信しなかった設定・通常営業時間は保持します。

ホームの「のくぷらの楽しみ方」の最後に会員ページの案内と、サイト設定の「お客さん用Discordの招待URL」へのリンクを表示します。会員ページのログイン画面にも同じ招待リンクを出します。

ホーム最下部の募集カードとフッターから `/recruit` のキャスト・スタッフ募集ページへ進めます。運営メニューの「募集ページ」で、冒頭の見出し・紹介文・写真・写真の左右配置、各セクションの追加・削除・並べ替え・表示切替・列数・背景、紹介カードや募集要項の各項目、応募案内を編集できます。セクションと各項目はそれぞれ12個まで。保存前のプレビューは公開ページと同じ描画を使い、保存した内容だけを反映します。応募先のGoogleフォームURLもここで変更でき、サイト設定の「募集フォームのURL」と共通です。URLが空欄なら受付準備中と表示し、リンクを隠します。応募回答はGoogleフォーム側で管理し、サイトには保存しません。

運営がキャスト紹介を登録し、本人のDiscordアカウントを紐付けると、本人は `/staff` の「キャスト紹介」で紹介写真・ひとこと・プロフィール・X/YouTubeのURLを更新できます。公開中なら保存後すぐにHPへ反映されます。非公開の紹介も本人が編集できますが、名前・表示順・公開状態・Discordの紐付けは運営だけが変更できます。本人用APIは許可した項目以外の更新や他人の紹介への変更を拒否します。紹介写真のアップロード先も本人用の権限で確認し、他人の画像IDやチェキを紹介写真として指定できません。「プレビュー」では保存前の入力を、公開ページと共通のプロフィール・一覧表示で確認できます。運営ページのキャスト編集でも、新規登録・既存編集のどちらでも同じプレビューを利用できます。選択した写真は端末内で3:4（900×1200px）に切り抜き、位置・拡大率を調整してから保存用のWebP画像にします。新しく選んだ画像と登録済みの写真の両方を調整できます。公開一覧・お気に入りの写真も3:4で表示します。プレビューには「この内容で保存する」があり、そのまま保存できます。失敗した場合はエラーを表示してプレビューと入力を残します。「編集に戻る」で閉じても入力は残り、保存操作をするまで公開内容は変わりません。非公開の紹介写真も紐付けられた本人と運営だけが確認できます。

チェキは一斉送信のみです。運営ページのキャスト編集で、公開中のキャスト紹介に本人のDiscordアカウントを紐付けてください。紐付け先はスタッフページへログイン済みのアカウントから選べます。送信先は「そのキャストをお気に入り登録 AND 選択した開始済みの公開営業回にチェックイン済み AND 会員登録済み」の全員です。運営ロールでも別のキャストとして送信できません。VRChat連携の有無は条件にしません。

スタッフ画面で営業回と対象人数を確認し、書き込み済み画像・任意のメッセージを指定して送信します。個別検索・個別送信は利用できません。送信直前まで対象を再検証し、人数が同じでも対象者が変われば再確認を求めます。同じ送信操作の再試行は重複配信しません。画像はDriveに非公開で1枚だけ保存し、受取人ごとに配信・既読を記録します。最初の対象が0人でも登録できます。あとから対象キャストのお気に入り登録と対象営業回のチェックインを両方済ませた会員には、会員ページを開いた際にその営業回の送信済みチェキも追加します。取り消し済みのチェキは追加しません。取り消しは一斉送信単位です。過去の個別チェキも引き続き閲覧・取り消しできます。

送信後にお気に入りやキャストの紐付けを変更しても、配信済みチェキの受取人・送信者は変わりません。対象者の現在のDiscord所属は画像閲覧時に確認します。

来店は1営業1人1回。合言葉はサーバー側の秘密を使ってハッシュ化し、受付時間外は拒否します。出欠締切や送信回数制限もサーバーで確認します。

無料サービスの利用上限や障害時は機能を利用できない場合があります。勝手に有料プランへ切り替える設定は行いません。Driveの空き容量は運営が確認してください。休眠によるDBの手動再開を前提にしない構成です。

期限切れのログイン・認証途中・回数制限用の情報はAPI利用時に定期整理します。会員・来店・チェキ本体は自動削除しません。削除依頼は本人確認後に運営が対応してください。表示取り消しで、端末に保存済みの画像まで消すことはできません。

## デザイン

ホームと会員・キャスト・スタッフ・運営ページで、クリーム色の背景、紺色の文字、金色のアクセントと丸みのあるゴシック体を共通にしています。提供された `logo/svg` のSVGロゴと施設写真を使い、ヘッダーは白背景用の横長ロゴ、ホームのフッターは暗い背景用の横長ロゴです。指定コピーは「今宵、星降るドームで夜想曲を。」。営業日・キャスト・動画は実情報の登録前は準備中として表示します。

デザインの整理に [unslop by Damir](https://github.com/heydamir/unslop) を参考にしています。
